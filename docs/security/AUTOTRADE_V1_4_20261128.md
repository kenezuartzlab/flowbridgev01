3. `liveTransport.ts` is a distinct managed-effect orchestration path, not V1.3 mock paper transport: exact immutable calls, exact approve/revoke, route/fee gates, signed chain/account/calldata/nonce/gas/fee checks, durable reservation/state callbacks, pause/fence checks before effects, persist-before-broadcast, ambiguous crash recovery by receipts only, no second signature/submission, and final receipt actual amounts.
4. `managedSigner.server.ts` implements a concrete fetch-only policy-broker protocol (`POST /v1/transactions/sign`) for a non-exportable KMS signer. It sends exact transaction fields with an idempotency key, rejects redirects and malformed responses, and never stores a private key. This is **our broker contract**, not a claim that any vendor already provides it or that a KMS exists. Production entry `processManagedLiveEffect` always rejects `LIVE_DISABLED` before storage, signing or RPC effects.
5. `managedRpc.server.ts` validates operator/evidence configuration, chain 677, common block hash, head lag, age, independent receipt parity, canonical mined blocks and six confirmations. It decodes the exact Router V4 `SwapActivity` for native/token output, never a wallet balance delta. Broadcast checks the source lock before any HTTP request.
